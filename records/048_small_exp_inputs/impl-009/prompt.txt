    * Strictly follow predefined file naming conventions and coding styles.

3. **Use Pure DuckDB Syntax**:
    * All SQL code must be compatible with DuckDB.
    * **Do NOT** end SQL statements with a semicolon (`;`) at the end of the file.

4. **No dbt Syntax**:

    * **Do NOT** use the dbt `ref()` function.

modeling_spec:
  purpose: "Transform staging data into business-ready models that provide comprehensive Google Play analytics, user behavior insights, revenue optimization, and market intelligence"

  design_principles:
    intermediate_purpose: "Create reusable, business-centric data models that combine multiple staging sources and apply complex business logic for downstream analysis"
    mart_purpose: "Provide analysis-ready datasets optimized for specific business use cases and reporting requirements"
    grain_importance: "Each model must have a clearly defined grain to ensure data integrity and proper aggregation"
    modularity: "Models should be modular and reusable across multiple downstream use cases"

  intermediate_models:
    - name: int_google_play__user_behavior_metrics
      description: Daily app metrics by package and country, including installs/uninstalls, rolling averages, growth, churn, ratings, and segmentations.
      grain: One row per (package_name, country, date_day)
      source_models:
      - staging.stg_google_play__stats_installs_country (date_day, package_name, country, daily_device_installs, daily_device_uninstalls, active_device_installs)
      - staging.stg_google_play__stats_ratings_country (date_day, package_name, country, daily_average_rating, total_average_rating)
      business_logic: '1) Filter sources: - Installs source: keep rows where daily_device_installs, daily_device_uninstalls, and active_device_installs are each >= 0 (rows with NULLs or negatives are excluded). - Ratings source: keep rows where daily_average_rating and total_average_rating are both within 1.0 to 5.0 inclusive. 2) Left join ratings to installs on (date_day, package_name, country); missing matches leave rating fields NULL. 3) For each (package_name, country), ordered by date_day, compute: - 7-day rolling averages for device installs and device uninstalls using up to the last 7 days including the current day. - 30-day rolling average for device installs using up to the last 30 days including the current day. - Weekly install growth rate: percent change vs the value 7 days prior; returned only when the 7-days-prior value is > 0; rounded to 4 decimals. - Daily churn rate: daily_device_uninstalls divided by active_device_installs; returned only when active_device_installs > 0; rounded to 4 decimals. - Rating 7 days ago via a 7-day lag of daily_average_rating (may be NULL when data is missing). 4) Segmentations: - user_engagement_level: • High Engagement when avg_7d_device_installs >= 100, daily_churn_rate <= 0.05, and daily_average_rating >= 4.0. • Medium Engagement when avg_7d_device_installs >= 50, daily_churn_rate <= 0.1, and daily_average_rating >= 3.5. • Low Engagement when avg_7d_device_installs >= 10 and daily_churn_rate <= 0.2. • Otherwise At Risk (any NULL condition fails). - growth_momentum: • Accelerating if weekly_install_growth_rate > 0.1. • Growing if weekly_install_growth_rate is between 0.0 and 0.1 inclusive. • Stable if weekly_install_growth_rate is between -0.1 and 0.0 inclusive. • Declining if weekly_install_growth_rate < -0.1. • Otherwise New Market (e.g., when the rate is NULL). - rating_trend: • Rating Improving if the 7-day rating change is greater than 0.1. • Rating Declining if the 7-day rating change is less than -0.1. • Otherwise Rating Stable (also when inputs are NULL). 5) Final outputs: - avg_7d_device_installs, avg_7d_device_uninstalls, and avg_30d_device_installs are rounded to 2 decimals. - weekly_install_growth_rate and daily_churn_rate retain 4-decimal rounding from computation. - install_uninstall_ratio is daily_device_installs divided by daily_device_uninstalls only when uninstalls > 0; rounded to 2 decimals; otherwise NULL. - market_maturity is based on the unrounded 30-day rolling average of installs: >1000 Mature Market; >100 Growing Market; >10 Emerging Market; else Niche Market. - Keep only rows where date_day, package_name, and country are not NULL; grain is one row per (package_name, country, date_day).'
