You are reviewing the work of a data agent that has just finished a task. The agent wrote code, ran it, and looked at results. You will see its complete trajectory, together with the task, the specification and documentation it used, and an index of all available data.

Your job is to find the places where the agent's work may be wrong, and to rank them by importance. Do not solve the task, do not write code, and do not judge whether the agent's final answer is correct as a whole.

Look for two kinds of problems:
- Places where the agent's work does not match what the task, specification, or documentation requires: scope and filters, metric definitions, which column a business term refers to, handling of special cases (missing values, zero denominators, invalid values), and the required form, granularity, and type of the output.
- Places where the agent's work may rest on a wrong understanding of the data: what a field or value means, what a row represents, whether a key is unique, whether records match in a join, what nulls mean, units, formats, where counting starts, and the time range or entities the data covers.

Listing a possible problem is not a claim that it is a real error. Many will turn out to be fine; they are listed so that they can be checked later. A possible problem that is unlikely but would change the result a lot if it were real should still be listed, ranked lower.

Two kinds of problems are easy to miss, so check for them explicitly:
- Omitted steps: processing that the specification or documentation requires but the code does not perform.
- Unused materials: files, tables, or columns in the index that bear on the task but that the agent did not use.

Rank problems by importance, combining two things: how likely it is to be a real problem given the materials you can see, and how much the agent's result would change if it is. A possible problem that would change little should rank low.

Return a JSON object whose keys are the names of every table or result the agent produced. For each, give an object with:
- "items": an ordered list of the 10 most important possible problems, most important first. Each item has:
  - "problem": one sentence describing what may be wrong.
  - "about": "requirement" or "data".
  - "evidence_in_work": a short quote from the agent's code or output that shows where the problem is.
  - "source": a short quote from the task, specification, documentation, or index that the problem is based on, or null.
  - "importance": an integer from 1 (low) to 5 (high).
  - "reason": one short sentence explaining the importance.
- "fewer_reason": if you listed fewer than 10 items, explain why; otherwise null.
List fewer than 10 only if you cannot find 10 possible problems for that table or result.
