## int_netsuite2__cash_flow_forecasting

    - name: int_netsuite2__cash_flow_forecasting
      description: 12-month cash flow forecast per subsidiary using the last 36 months of analysis, with trend and seasonal adjustments and risk/action signals
      grain: One row per subsidiary_id per forecast_month
      source_models:
      - intermediate.int_netsuite2__cash_flow_analysis
      business_logic: '- History window: use the last 36 months of analysis data per subsidiary. - Aggregate historical trends per subsidiary: - Averages: monthly net, operating, investing, and financing cash flows (NULLs are skipped). - Volatility: standard deviation of monthly net and operating cash flows (NULLs are skipped). - Trend deltas: for net and operating cash flow, compute the difference between the average of the most recent six months and the average of earlier months when at least 12 months exist; otherwise set to 0. - Quarterly seasonality: average monthly net cash flow per calendar quarter (Q1/Q2/Q3/Q4). - Latest period: most recent analysis_month; historical_periods: count of months used. - Seasonal factors per quarter: - For each quarter, divide the quarter’s average net cash flow by the overall average; if the overall average is zero or missing, or the quarter average is missing, use 1. - Forecast generation: - Only subsidiaries with historical_periods >= 6 are forecasted. - Create 12 future offsets (1 to 12 months). - For each offset, forecast_month = latest_period plus the offset in months. - Choose the seasonal factor based on the forecast_month’s calendar quarter (Q1: Jan–Mar, Q2: Apr–Jun, Q3: Jul–Sep, Q4: Oct–Dec). - Forecast calculations per subsidiary and offset: - Net: (average net cash flow + net trend scaled by offset/6) × seasonal factor. - Operating: (average operating cash flow + operating trend scaled by offset/6) × seasonal factor. - Investing: average investing cash flow × seasonal factor. - Financing: average financing cash flow × seasonal factor. - 95% bounds: lower = forecast net − 1.96 × net volatility; upper = forecast net + 1.96 × net volatility (results are NULL when volatility is NULL). - Confidence: - High: historical_periods >= 24 and net volatility <= 30% of the absolute average net. - Medium: historical_periods >= 12 and net volatility <= 50% of the absolute average net. - Low: historical_periods >= 6. - Very Low: otherwise. - Horizon: Short-term for offsets 1–3, Medium-term for 4–6, Long-term for 7–12. - Windowed metrics within each subsidiary ordered by offset: - Cumulative forecast cash flow: running sum of net forecasts up to the current offset (skips NULLs; returns NULL if the entire window has only NULLs). - Cumulative forecast operating cash flow: running sum of operating forecasts up to the current offset (skips NULLs; returns NULL if the entire window has only NULLs). - Three-month forecast average: average of net forecasts over the current and two prior offsets (skips NULLs; returns NULL when the frame contains only NULLs; may be based on fewer than three rows at the start). - Trend, risk, actions, and dates: - Trend: compare the current net forecast to the prior month’s net forecast within the subsidiary; classify as Positive Trend (both positive), Negative Trend (both negative), Improving (current positive, prior negative), Deteriorating (current negative, prior positive), else Stable (including when the prior is missing). - Risk level: - High Risk: current net forecast < 0 and cumulative net forecast < 0. - Medium Risk: current net forecast < 0 or cumulative net forecast < 0. - Low Risk: lower bound < 0. - Minimal Risk: otherwise. - Recommended action: - Critical: Immediate Cash Management Required when current net forecast < 0 and cumulative net forecast < −2 × absolute operating forecast. - Urgent: Review Short-term Liquidity when current net forecast < 0 and horizon is Short-term. - Consider Financing Options when cumulative net forecast < 0. - Monitor Cash Flow Closely when lower bound < 0. - Continue Current Strategy otherwise. - forecast_date is set to the current date at execution. - Output and ordering: - Return the selected fields and sort by subsidiary_id, then forecast_month_offset. - Create a deterministic ID by hashing the concatenation of subsidiary_id, an underscore, and the string form of forecast_month.'
      columns:

        data_type: VARCHAR
        description: Subsidiary identifier and grouping key; exactly one row per subsidiary_id and forecast_month
        tests:
        - not_null
      - name: forecast_month
        data_type: TIMESTAMP
        description: Latest historical analysis_month plus forecast_month_offset months
      - name: forecast_month_offset
        data_type: BIGINT
        description: Offset in months from the latest_period, generated as 1–12, used for window ordering and trend scaling
      - name: forecast_horizon
        data_type: VARCHAR
        description: Short-term for offsets 1–3, Medium-term for 4–6, Long-term for 7–12
      - name: forecast_net_cash_flow
        data_type: DOUBLE
        description: Projected net cash flow using average plus offset-scaled trend, multiplied by the seasonal factor; no rounding
      - name: forecast_operating_cash_flow
        data_type: DOUBLE
        description: Projected operating cash flow using average plus offset-scaled trend, multiplied by the seasonal factor; no rounding
      - name: forecast_investing_cash_flow
        data_type: DOUBLE
        description: Projected investing cash flow as average multiplied by the seasonal factor; no rounding
      - name: forecast_financing_cash_flow
        data_type: DOUBLE
        description: Projected financing cash flow as average multiplied by the seasonal factor; no rounding
      - name: forecast_net_cash_flow_lower_bound
        data_type: DOUBLE
        description: Lower 95% bound equals forecast net minus 1.96 times net volatility; NULL when volatility is NULL
      - name: forecast_net_cash_flow_upper_bound
        data_type: DOUBLE
        description: Upper 95% bound equals forecast net plus 1.96 times net volatility; NULL when volatility is NULL
      - name: forecast_confidence
        data_type: VARCHAR
        description: Confidence label based on historical_periods and net volatility relative to the absolute average net; NULL comparisons do not match and fall through
      - name: cumulative_forecast_cash_flow
        data_type: DOUBLE
        description: Running sum of forecast_net_cash_flow within subsidiary ordered by offset; skips NULLs and returns NULL when the window contains only NULLs
      - name: cumulative_forecast_operating_cash_flow
        data_type: DOUBLE
        description: Running sum of forecast_operating_cash_flow within subsidiary ordered by offset; skips NULLs and returns NULL when the window contains only NULLs
      - name: three_month_forecast_avg
        data_type: DOUBLE
        description: Moving average of forecast_net_cash_flow over the current and two prior offsets; skips NULLs and returns NULL when the frame contains only NULLs
      - name: forecast_trend
        data_type: VARCHAR
        description: 'Trend classification based on current versus prior net forecast by subsidiary ordered by offset: Positive Trend, Negative Trend, Improving, Deteriorating, else Stable when no rule matches or the prior is missing'
      - name: forecast_risk_level
        data_type: VARCHAR
        description: 'Risk level based on net and cumulative net forecasts and the lower bound with precedence: High, Medium, Low, Minimal; NULL comparisons fall through'
      - name: recommended_action

        description: 'Action recommendation with precedence: Critical, Urgent, Consider Financing Options, Monitor Cash Flow Closely, else Continue Current Strategy'
      - name: net_cash_flow_volatility

      - name: historical_periods

        description: Count of historical months used (last 36 months); only subsidiaries with at least 6 months are forecasted
      - name: forecast_date
        data_type: DATE
        description: Current date at execution when the forecast was generated
      - name: cash_flow_forecast_id
        data_type: VARCHAR
        description: Deterministic ID created by hashing subsidiary_id, an underscore, and the string form of forecast_month

        - not_null

      business_logic: 'Compile intermediate checks and summarize into a final unioned report ordered by report_type and quality_grade (ascending): - source_table_stats (per source table snapshot with current time): - Transactions: total records; unique records by distinct transaction_id; counts of null transaction_id (null_primary_keys), null transaction_date (null_dates), null entity_id (null_subsidiaries), null status (null_status); earliest_date = minimum transaction_date; latest_date = maximum transaction_date. - Transaction lines: total records; unique records by distinct transaction_line_id; counts of null transaction_line_id (null_primary_keys), null transaction_id (null_foreign_keys), null entity_id twice for both null_accounts and null_amounts; earliest_transaction = minimum transaction_id; latest_transaction = maximum transaction_id. - Customers: total records; unique records by distinct customer_id; counts of null customer_id (null_primary_keys), null company_name (null_names), null email_address (null_emails), null date_first_order_at (null_creation_dates); unique_names = distinct company_name count; unique_emails = distinct email_address count. - referential_integrity_checks (three left-join checks; integrity percentages rounded to two decimals): - transaction_lines_to_transactions: base = transaction_lines; matched = joined transaction_ids; orphaned = base minus matched; integrity = matched/base × 100 (two decimals); timestamp = current time. - transaction_lines_to_entities: base = transaction_lines; matched = joined entity_ids; orphaned and integrity computed as above; timestamp = current time. - transactions_to_entities: base = transactions; matched = joined entity_ids; orphaned and integrity computed as above; timestamp = current time. - business_rule_validations (four rules; compliance percentages rounded to two decimals; timestamp = current time): - transaction_id_uniqueness: violations = total transactions minus distinct transaction_id; compliance = distinct/total × 100. - customer_id_uniqueness: violations = total customers minus distinct customer_id; compliance = distinct/total × 100. - future_transaction_dates: violations = transactions with date more than one day in the future; compliance = transactions with date not more than one day in the future divided by total × 100. - balanced_journal_entries: sum netamount per transaction_id; violations = distinct transactions with absolute total_amount greater than 0.01; compliance = distinct transactions with absolute total_amount at most 0.01 divided by total × 100. - data_completeness_analysis (customers_contact_info and transaction_lines_account_assignment) is computed but not used in final output. - overall_quality_summary (single row): - completeness_score = average across source_table_stats of: for transactions, 100 if (null_primary_keys + null_dates + null_subsidiaries) equals 0 else 70; else Referential Integrity Issues if consistency_score < 80; else Business Rule Violations if accuracy_score < 80; else No Major Issues. - recommended_action: Immediate Data Cleansing Required if overall_quality_score < 70; Regular Data Quality Monitoring Recommended if < 85; otherwise Maintain Current Data Quality Standards. - tables_assessed = number of source_table_stats rows; integrity_checks_performed = number of referential_integrity_checks rows; business_rules_validated = number of business_rule_validations rows. - quality_assessment_id = MD5 of the assessment_timestamp as text. - Table Statistics rows (one per source_table_stats row; report_type = ''Table Statistics''): - quality_grade = table_name. - primary_concern = "Records: {total_records}, Unique: {unique_records}, Null PKs: {null_primary_keys}". - recommended_action: - Transactions: "Date Range: {earliest_date} to {latest_date}". - Transaction lines: "Date Range: {earliest_transaction} to {latest_transaction}" (transaction_id values). - Customers: "Date Range: {unique_names} to {unique_emails}" (distinct counts occupying those positions). - If any concatenated component is null, the whole string is null. - metric columns not applicable are null; assessment_timestamp = check_timestamp; quality_assessment_id = MD5 of table_name concatenated with check_timestamp as text. - Integrity Checks rows (one per referential_integrity_checks row; report_type = ''Integrity Checks''): - overall_quality_score = integrity_percentage (two decimals). - quality_grade = check_name. - primary_concern = "Matched: {matched}/{total}" using the matched join count over the base record count of the check. - recommended_action = "Orphaned Records: {orphaned_records}". - metric columns not applicable are null; assessment_timestamp = check_timestamp; quality_assessment_id = MD5 of check_name concatenated with check_timestamp as text. - Final ordering: by report_type then quality_grade ascending; casing and spacing in constructed strings are preserved.'
      columns:

      - name: overall_quality_score

        description: 'Overall row: average of the three scores rounded to two decimals; Integrity rows: integrity percentage; Table Statistics: NULL'
      - name: quality_grade

      - name: primary_concern
