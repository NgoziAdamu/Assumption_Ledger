# 错误机制标注手册（v3，试用版）

版本：v3，2026-10-31。适用于 DAComp DE-Impl 和 KramaBench。在 v2 的基础上换成新的错误机制分类；试点批（任务 034）标完后修订，再冻结用于其余批次。修订记录见第 12 节。

在 v3 冻结之前，任何类别定义、判定门槛的改动都要记录日期和理由；冻结后改定义的，已标的全部按新定义重标。

## 1. 要回答的问题

对每个判错的对象（DAComp 的一张表、KramaBench 的一道题），回答：
1. **它为什么和标准答案不一致？** 找出错误点，逐个归类（第 3～6 节）。
2. **agent 有没有把相关的选择或缺口说出来？**（第 7 节）
3. **探索阶段的错误点，能定下前提的材料有没有出现在 agent 看到的内容里？agent 有没有曾经按正确的理解做过？**（第 8 节）

- 判错按官方评分，不重新定义"对错"。DAComp 中间层及以后按 CS 口径：上游一律用标准答案，只看这一张表自己。KramaBench 按官方评测加 029 的补评结果。
- 没有预期的类别分布。每个类别都需要同等强度的证据。

## 2. 分类的对象和依据

- **对象是错误点**：agent 的输出里一处可以单独修改、修改后与标准答案的差距会变化的地方。一个对象可以有多个错误点。
- **依据**：这个错误点背后没有被确立的前提，在 agent 的工作里起什么作用，怎样变成了答案的一部分。
- **两个阶段按前提的作用分，不按它在轨迹里出现的时间分**：
  - **Exploration phase**：agent 建立对数据和对要求的理解。这里出错的前提是理解本身错了。
  - **Conclusion phase**：agent 把工作变成交出去的答案，包括在几种做法之间选择、决定什么算做完、按要求的样子交付。这里出错的前提是"这样交就行"。一个选择即使在轨迹早期就做了，只要属于"把工作变成答案"的选择，也算 Conclusion phase。

## 3. 判断顺序（对每个错误点）

1. **先排除不属于前提问题的**：
   - agent 的想法是对的，代码没写出这个想法 → 代码写错。
   - 差异不是 agent 处理方式造成的 → 其他（第 6 节）。
   - 标准答案所用原始数据本身不同 → 不可评估。
2. **改掉它是否只改变答案的呈现、不改变算出来的值？** 是：
   - 题面或规格明确规定了形式或粒度 → **Form Mismatch**；
   - 没有明确规定 → 其他。
3. **交出去的东西，在某种说得通的读法下，是不是题目要的那个东西？** 不是，又当作完成交付 → **Quiet Downgrade**（看第 7 节决定是否改为"已说出的降级"）。
4. 是的话，看这个错误点背后的前提**能不能用当时拿得到的材料定下来**。顺序：
   1. 题面按自然读法；
   2. benchmark 的其他材料：DAComp 的 `data_contract.yaml` 等文档；KramaBench 数据湖里的说明文件、Excel 的 README 页、文件开头的注释、变量说明；以及数据本身（数据结构、agent 当时能查到的数据）；
   3. 领域公认约定：必须写出约定是什么，拿不准就不用这一条。

   结果：
   - 能定，且知道一件关于数据的事实就能改对 → **Data Misconception**；
   - 能定，且知道题目或规格的意思就能改对 → **Intent Misreading**；
   - 定不了 → **Unstated Choice**（看第 7 节决定是否改为"已说出的选择"）。

KramaBench 的子任务 agent 看不到，只能用来看标准答案是怎么做的，不能当作 agent 应有的依据。DAComp 不能用标准答案的选择作为对错依据。

## 4. 五种的定义

### Exploration phase

**Data Misconception**：agent 对数据本身的理解错了，而当时拿得到的材料能定下来。
- 包括：字段或取值的含义、覆盖范围、单位、格式、从几开始数、时间方向、记录之间怎么对应（是否唯一、能否都匹配上、一行代表什么、外键指向哪张表）。
- 例：OMNI 格式说明写字段从 1 开始数，agent 按从 0 数取了另一个字段；数据从 2000 年开始，agent 按 2002 年开始算；默认 id 唯一、默认每个对话都有 part，实际不成立。

**Intent Misreading**：agent 对"要的是什么"的理解，和题面或规格能定下的意思不符。
- 包括：范围、限定条件、指标怎么算、规格里写明的业务规则、业务术语对应数据里的什么。第一次读就读错的，和早先读对、后来跑偏的，都算。
- 例：题面问全州海滩，agent 只算波士顿港；契约规定缺失补 0，agent 留 NULL；契约规定非法枚举置空，agent 删整行。

### Conclusion phase

**Unstated Choice**：拿得到的材料都定不了这个前提，有几种说得通的读法或做法；agent 选了一种，没有针对这一处具体说出来。
- 例：距离用平面欧氏还是大圆；衰减率用端点差还是回归斜率；按县平均还是按州合计；时间文本用哪种解析方式；hash 怎么拼接。
- 描述时只说"差异取决于材料没定的选择"，不说 agent 做错。

**Quiet Downgrade**：交出去的东西，在任何说得通的读法下都不是题目要的那个东西，agent 却当作已完成交付，且没有针对这一处具体说出来。
- 包括：占位值、常量、原始表有候选列却不做判断就整列填 NULL、用替代量代替要求的量、自造要求的输入、只交汇总、直接透传别的结果。

**Form Mismatch**：算出来的内容是对的，但交出去的形式或粒度和题面或规格**明确规定**的不同。改掉它只改变答案的呈现，不改变算出来的值。
- 包括：多带说明文字或多余字段、类型或枚举标签与规定不符、没按规定取整、规定要一个值却交了一句话。

## 5. 边界规则

**Data Misconception 和 Intent Misreading**
- 知道一件关于数据的事实就能改对的，归 Data；知道题目或规格的意思就能改对的，归 Intent。
- 数据的含义本身很清楚（例如列名就说明了用途），agent 缺的是把题目的意思用上去的，归 Intent。
- 规格**规定了做法**（取哪一列、怎么过滤、用什么表达式），agent 没照做或理解成别的，归 Intent（只改呈现的归 Form Mismatch）。规格**只说明了数据的性质**（例如"项目可能缺失""可能重复"），agent 的代码却依赖相反的性质，归 Data。
- 规格给出了可以在评测引擎中直接执行的写法时，按字面执行的效果为准，不推测"本意"。
- 数据违反了这一列本身含义决定的硬约束（纬度超出正负 90 度、计数为负、百分比超过 100），agent 没发现、没处理，归 Data。只是业务上要不要剔除的选择（值本身合法），归 Unstated Choice。
- agent 因为误以为数据有问题（例如以为源表不存在，实际没问题）才换表或填空值，归 Data，不归 Quiet Downgrade。

**探索阶段和 Unstated Choice**
- 材料能定下来的，归探索阶段两种，哪怕 agent 自己算出过几个候选、交了错的那个。
- 规格没给源列对应关系、agent 选了某一列：只有 agent 当时能看到的数据给出了明确结论（例如所选列与相关表完全匹配不上，另一列能匹配），才归 Data；否则归 Unstated Choice。

**Quiet Downgrade 和 Unstated Choice**
- 要求的东西或输入不存在，agent 造了一个替代品当作它，归 Downgrade。
- 东西存在、只是定义没定，归 Choice。
- 原始数据里根本没有对应的列、填 0 还是填空没规定，agent 留空或填默认值，归 Choice（不算造替代品）。
- 原始表里有看得出来的候选列，agent 没做任何判断就填了空，归 Downgrade。

**Form Mismatch 和其他几种**
- 改掉它会改变算出来的值的，不算 Form Mismatch。例如按县算了而题目要州级汇总，这会改变数值，按第 3 节第 4 步判断。
- 题面和规格都没规定形式的，归"其他"，不计入。规格只给出了含义、没写死具体字符串或标签，且差异只在文字写法上（分类本身一致）的，也归"其他"。
- 代理键、hash 键的生成方式没规定，导致键值不同：键值是算出来的，不算只改呈现，按 Unstated Choice 处理。你认为不合适的，在"规则问题"里写明。
- KramaBench 运行时系统提示里有一句通用要求（"答案必须是题目所要求形式的 Python 值"），**不算**明确规定。只在字段"系统提示是否适用"里记录，供另报口径用。

## 6. 分类之外的

- **代码写错**：agent 的想法是对的，代码没写出这个想法。想法可以从思考、报告中看出，也可以从代码自身的明确证据看出（例如同一个映射里先写了正确的列，后面又被覆盖）。看不出想法时不归这一类。
- **其他**：差异不是 agent 处理方式造成的，换个评测条件就算对。包括：
  - 标准答案与规格、题面或子任务不一致（例如 agent 按契约的类型或唯一性输出，标准答案没有）；
  - 契约明确允许任意顺序、差异只在并列项的先后（需用诊断查询确认其余内容一致）；
  - 形式没有明确规定而形式不同（见第 5 节）。

  措辞保持中性，只描述事实，不评价 benchmark。
- **不可评估**：
  - DAComp：表依赖的原始表，agent 留存库与初始库一致、而标准答案库不同，经诊断确认后标不可评估。agent 自己运行中改动了原始数据的，照常标注，并在轨迹里找出改动的步骤和原因。
  - KramaBench：标准答案所需文件不在数据湖里。
- **无法判定**：只用于确实看不出原因，不用于"原因清楚但不满足某个门槛"。
- **未交卷**（KramaBench astronomy-hard-11）：只记录，不分析。

## 7. 主要原因、参与因素、多因并列

**规模**
- DAComp 沿用 v2：先按**行**数（仅 agent 有的行 + 仅标准答案有的行 + 共同键中至少一列不同的行，整表口径含评测键）；比不出时按**格子**数。
- KramaBench：数值答案按与标准答案的差距；列表或集合按两边不同的元素数；字符串、布尔值按是否一致。

**主要原因**
- 每个错误点单独修一次，其余不动，分别重跑。规模减少最多的是主要原因。
- 仍然并列的，记"多因并列"，逐项列出每个并列项的类别。所有并列项类别相同时，直接记该类别。
- 跨阶段的并列照记，统计时单列一行。
- 每处单改规模都不减少、必须几处一起改才减少的，记"只能组合修复"，并列出各项类别。

**参与因素**
- 主要原因之外的错误点，只改这一处规模有所减少（不要求减少一半）的，记为参与因素，并写明类别。
- 只改这一处、规模完全没变、但它确实是 agent 没确立就依赖的前提的，不算参与因素，加标记"存在未确立的前提，但不是判错原因"。

**所有类别用同一套规则**
- 主要原因按规模减少最多的定；参与因素只要单改后规模有所减少。任何类别都不设额外的减少幅度门槛。

**Data Misconception 的证据要求**
- 必须写出 agent 依赖的那句关于数据的话 P（例如"每个客户 ID 只出现一次"）。
- 必须证明 P 不成立：用 agent 当时能看到的数据做核实查询，或者引用能定下它的材料原文（文档、变量说明、格式说明）。
- 写不出 P、或证明不了 P 不成立的，不归这一类。

## 8. 每个错误点要填的字段

1. **类别**（第 4、6 节），把握（高、中、低）。拿不准就写原因。
2. **是否说出**：沿用 v2 的四档，每个错误点都填，附事件编号和原句。
   1. 针对本处的具体说明；
   2. 只有通用策略说明；
   3. 看到了但没提；
   4. 没有迹象。

   主口径：Unstated Choice 和 Quiet Downgrade 的四档为"针对本处的具体说明"时，类别改记为**已说出的选择**或**已说出的降级**；其他三档仍记原类别。探索阶段两种和 Form Mismatch 不因此改类别，只记录四档。
3. **证据在场**（只对 Data Misconception、Intent Misreading 填）：单凭它就能定下这个前提的材料，是否出现在 agent 实际看到的内容里。
   - 填"是"时，附事件编号和原文片段。被截断的输出不算看到。
   - DAComp 要逐张确认：契约里相关的那一段，在 agent 读取契约的输出中有没有被截断。
   - 只出现了"相关的东西"、但单凭它定不下来的（例如只看到了列名、没看到匹配结果），填"否"，并写明看到了什么。
4. **曾经理解对过**（只对探索阶段两种填）：agent 在轨迹里是否曾按正确的理解写过代码或算出过结果。是的话附事件编号。
5. **系统提示是否适用**（只对 KramaBench 的 Form Mismatch 和"其他：形式没规定"填）：KramaBench 运行时的那句通用要求是否涉及这一处。

## 9. 查询和重跑

- **优先复用已有的证据**：DAComp 019～025 的单改重跑、核实查询、诊断查询和轨迹引句；KramaBench 030 的宽松比对、032 的核实查询。复用的写明来源文件。
- **只在需要时新做**：
  - 新识别出、以前没单独修过的错误点；
  - 验证"只改呈现就能对上"（判 Form Mismatch 或"其他：形式没规定"时）；
  - 核实证据在场（主要是读轨迹原文，一般不用查库）。
- **核实查询**：只查 agent 当时能看到的数据。每个对象不超过 5 条。
- **诊断查询**：可以查标准答案，只用于定位差异，确认是不是"其他"或不可评估。不计入那 5 条。
- **重跑**：只改指定的一处，其余字节不动，在私有副本中执行。DAComp 按 L0–L3 比较，报告行数和格子数口径的规模，并列出改动前的同口径数字；涉及运行时间的表，基线和所有修改用同一个固定时间。staging 的原始数据用 agent 留存库里的 raw 表。数据库一律只读打开原件。

## 11. 规则问题

遇到本手册覆盖不了、或者两种读法都说得通的情况，按你认为最合理的方式标，并在结果末尾"规则问题"一节写明：是哪个对象、哪两种读法、你选了哪种、为什么。不要自行修改本手册。

## 12. 修订记录

v3（2026-10-31，试用版）：
- 类别换成两个阶段五种：Data Misconception、Intent Misreading、Unstated Choice、Quiet Downgrade、Form Mismatch；新增"已说出的选择""已说出的降级"。
- v2 类别的去向：
  - U → Data Misconception；
  - C → Intent Misreading 或 Form Mismatch；
  - A → Unstated Choice 或"其他"（只差文字写法、形式没规定的）；
  - D → Quiet Downgrade；
  - I、O、X、不可评估保留。
- v2 的补充规则按新类别重写，写入第 5 节。
- 新增字段：证据在场、曾经理解对过、系统提示是否适用；四档改为每个错误点都填。
- 适用范围扩到 KramaBench。
- 2026-10-31 用户确认：取消 v2 对未核实假设"作为主要原因须完全对上或差异减半"的门槛。理由：v3 中五种类别地位平等，判定规则统一，不为某一类单设门槛。防止往这一类里凑的要求改为：必须写出 P，并用 agent 可见数据或材料原文证明 P 不成立（第 7 节）。
