# pilot 实验现成资源调查

## 任务

调查 RADAR 的 DS-STAR 原始运行轨迹、错误类型标注和 runtime 代码，核实 DS-STAR 开源实现，以及 KramaBench、DA-Code、DABStep 的获取方式、任务数、评分和 license；辨认笔记中的 DAB。调查日期：2026-10-27，时区 Asia/Singapore。

本任务只读取资料、检查文件结构和记录资源元数据，未运行 agent、未运行 benchmark 或评分器、未进行错误归因或实验分析。

## 结论

截至调查日，未找到可归属于 RADAR 论文的公开 DS-STAR 原始轨迹、405 条静默错误的逐条标注或 RADAR runtime 代码；这表示本次检索未找到，不能证明作者没有在其他位置发布。另核实到 DABStep 上一个第三方 DS-STAR 提交，包含 450 条最终代码、答案及另表评分，但没有完整执行输出或错误类型标注。DS-STAR 已有 Google 官方公开实现及多个第三方实现；三个指定 benchmark 均有公开获取入口，但 DA-Code 的 HF 文件有访问门槛，KramaBench 的数据 license 声明不完整。存在独立名为 DAB 的 DataAgentBench，与 DABStep 是不同项目。

**评分方式，按各项目自己的定义登记：**

- **KramaBench：** 主指标是端到端答案分数，单题归一到 `[0,1]`，按任务平均。精确字符串和精确数字为 0/1；近似数字采用 `1 / (1 + relative absolute error)`；list 用 F1；近似字符串采用 ParaPluie/LLM 语义判断。另提供 pipeline design 的关键功能覆盖率，以及 sub-task implementation 评分。论文 §2.2、Appendix G 给出这些定义；它不是统一二元 accuracy。[论文 PDF](https://arxiv.org/pdf/2506.06541v3)。仓库 README 另列 BLEU/ROUGE、code-eval 等指标，本报告保留其与论文说明的差异，未运行 harness 判定当前默认组合。
- **DA-Code：** 按任务产物评分。表格、数据库或 JSON 比较任务要求的列/值；图表比较数值数据和指定图形属性，匹配为 1，否则为 0；ML 按 F1、MAE、Silhouette 等任务指标计算后，按 baseline 与 best bound 归一到 `[0,1]`。`evaluate.py` 使用 gold 文件和每题 eval 配置；不能把所有任务分数都视为二元正确/错误。[论文 §3.3–3.4 与 Appendix C](https://arxiv.org/html/2410.07331v2#S3.SS4)、[evaluate.py](https://github.com/yiyihum/da-code/blob/main/evaluate.py)。
- **DABStep：** 每题 factoid 答案得到 boolean 正确/错误，再聚合 accuracy；不使用 LLM judge。公开 scorer 对数字设容差，字符串做规范化与模糊匹配，list 做拆分、排序及逐项比较。[官方介绍](https://huggingface.co/blog/dabstep)、[scorer.py](https://huggingface.co/spaces/adyen/DABstep/blob/main/dabstep_benchmark/evaluation/scorer.py)。正式 450 题的公开 `answer` 字段均为空，10 个 dev 题均有答案；正式评分通过官方提交入口，不能仅凭公开 tasks 文件在本地核对全部 gold。
