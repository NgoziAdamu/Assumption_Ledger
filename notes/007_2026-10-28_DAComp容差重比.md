## 详细发现

### 1. 四级比较的精确定义

| 级别 | 值比较 |
| --- | --- |
| L0 | 沿用原官方整表判定；按键值采用官方字符串规范化：COALESCE(LOWER(TRIM(CAST(value AS VARCHAR))), 'null')。不额外做数值或日期容差。 |
| L1 | 在 L0 上，十进制或科学计数法字符串按精确数值相等比较；true/t 和数值 1 统一，false/f 和数值 0 统一。1.0、01、1e0 也与 1 相等。其他字符串保留 L0 规则。 |
| L2 | 在 L1 上将数值精确四舍五入到两位小数，采用 ROUND_HALF_UP；负数中点远离 0，例如 -1.005 → -1.01。 |
| L3 | 在 L2 上，能明确解析的 ISO 日期或 SQL/ISO timestamp 只保留所示日期；时间及其小数部分被舍弃。 |

数值解析不经过 binary float，不把超过 2^53 的整数混同；实现按十进制系数/指数精确处理，独立校验使用 Decimal 和 quantize。布尔统一作用于所有比较列中的这些表示，不推断字段业务类型。空串不自动转成 0；SQL NULL 与字面字符串 null 继续沿用 L0 合并口径。±Infinity 统一表示，NaN 保留 L0 字面规则。不猜测货币符号、千分位或其他自定义数字格式。

日期只接受明确可解析的 ISO/SQL 日期与日期时间。不猜测斜杠日期的月日顺序、Unix 时间或数字 ID；无日期部分的纯时间不转换。日期取自各自 CAST 后的字符串，不额外按时区换算成同一瞬间。例如不将一个带偏移 timestamp 先换算到另一时区后再取日期。测试明确覆盖“同日期不同时刻可在 L3 相等”和“同一瞬间可能表示为不同日期”的情况。

### 2. 固定键与“完全匹配”的范围

- 沿用每张表在 004/005 中实际使用的键列，且键值始终采用 L0 规范化；L1–L3 只改变被比较的值，不重新挑键、不重新按数值或日期对齐键。
- 比较列使用原记录的 official_compare_cols_available，即官方配置与双方实际列的可用交集。所有级别都使用同一列集；不额外加入原配置之外的列或类型差异。列集和未参加官方比较的列都写在每条记录里。
- **共同键内匹配**：只取两侧都存在的原键，要求每个共同键内，完整比较行元组及其重复次数相同。只在某一侧出现的键不进入这个判断，因此共同键内匹配不等于整表匹配。没有共同键时本项不可比较。
- **整表匹配**：要求预测/gold 行数相同，并且全部比较行元组的多重集合一致，包括重复次数，不使用键作额外限制。放宽值比较不会删除或新增行。
- 004/005 对非唯一键的逐列计数含多重集合下界，单靠“所有列的下界都是 0”不能证明完整行一致。本次“完全匹配”用整行元组多重集合判定；旧的 L0 列差异数仍原样保存在 baseline_l0_mismatching_official_columns 中，不改旧记录。

因此，两列计数不是同一种通过条件；即使共同键内在 L0 已匹配，整表仍可能不匹配。相反，放宽后的整表行多重集合也可能相同，而固定 L0 键没有可对齐的共同键。这里只并列记录这两种判断，不给出原因标签。

### 3. L3 仍不一致的列与行数

[L3 仍不匹配记录](../records/007_l3_remaining.jsonl) 收录 304 张至少在按键或整表一项仍不匹配的表。每条记录均保留旧报告的预测/gold 行数、行数差、键列、仅预测键数、仅 gold 键数、共同键数，以及 L3 逐列计数。也可直接在 [CSV](../records/007_tolerance_tables.csv) 的 keyed_level、whole_level 和 l3_columns 中筛选。

- 一对一共同键：one_to_one_mismatch_rows 是精确值差异行数。
- 非唯一共同键：先逐列抵消相同值的出现次数，剩余预测 P 次、gold G 次，至少 min(P,G) 对值不同；nonunique_key_minimum_value_mismatch_pairs 记录这一项。mismatch_rows_or_minimum_pairs 是精确行数加这个下界，不声称唯一逐行配对。
- pred_unmatched_value_occurrences / gold_unmatched_value_occurrences 分别给出两侧未抵消的出现次数；即使强制不同值对数为 0，未抵消次数也可能非 0。L3 不一致列按这两个次数是否仍非 0 列出，避免漏掉重复次数差异。
- 共同键内逐列边际多重集合全部相等，仍不必然意味着完整行的组合相同；此类情况仍按整行元组判断。本次此标记为真的表数是 2，字段为 l3_keyed_rows_differ_with_equal_column_marginals。
- 没有共同键时 L3 列差异记为 null，不虚构逐行对应；旧行数和键差异仍完整保留，整表判断仍独立给出。缺表也保留原记录并标为不可比较。

每张表的 baseline_alignment、baseline_prediction_rows、baseline_gold_rows、baseline_row_delta 与 004/005 原记录逐项相同；本次另外计算的 current_key_statistics 仅用于核对，没有覆盖原值。[不可比较条目](../records/007_unavailable.csv)。

### 4. 实际计算与校验

小表使用 Python 加权 Counter；大表在 `data/007_tolerance_scratch/` 用 DuckDB 临时库、加权行计数和不同值字典进行比较。输入库全部以 READ_ONLY 读取，临时数据不进 git。重复行先聚合为权重，仍保留完整行组合及重复次数。

若行数不同，整表在所有级别都不匹配；若 L3 下某列的多重集合仍不等，完整行多重集合在更严格的各级也不可能相等。实现用这些必要条件减少重复计算；可能匹配的情形再检查完整行元组。共同键一对一且全表行数不同的大表用不同值对的频次表计算各级精确列差异。没有进行多对多笛卡尔配对，也没有抽样代替全量比较。

L1–L3 的匹配使用完整规范化行元组及计数，而不是拼接字符串 hash 作为严格相等的证明。L0 固定使用原官方结果，独立行元组核对的单独差异列在 l0_tuple_vs_official_discrepancies；impl-028 的原官方结果已另外只读复核。原官方标记、原行数/键统计均未被覆盖，baseline_discrepancies 为空，所有级别的匹配布尔值满足逐级只放宽的关系。
