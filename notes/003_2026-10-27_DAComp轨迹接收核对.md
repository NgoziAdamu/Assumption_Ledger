### 2. 逐步记录究竟包含什么

独立解析了 30 题的原生事件、`model_calls.jsonl`、命令索引和 SQL 版本索引，检查对象限定为 `source=agent`、`action=run` 的 bash 工具请求，不混入框架初始化或评分器内部的 SQL。[事件核对](../records/003_dacomp_event_checks.json)、[模型记录核对](../records/003_dacomp_model_record_checks.json)、[SQL 版本核对](../records/003_dacomp_sql_version_checks.json)。

- **模型输出：** 832 个 bash 动作均包含原生 `model_response.choices[].message`，其中对应 `tool_call_id` 的工具参数与动作 `args.command` 逐字相符。模型的文本 `content` 可以为 null；此时实际对外输出是 `tool_calls`，不能把它当作缺失响应。29 个 finish 也均有模型响应和 `final_thought`。去重后共有 795 个成功模型 response id；调用账本为 795 success、1 failed，失败调用不能虚构模型输出。
- **命令与 SQL：** `args.command` 保存实际提交的 shell 命令，包括内联 SQL、读写 SQL 文件和调用脚本的命令；最终 SQL 保存于各题工作区。侧录索引包含 1,534 份内容版本，重新核对各版本的字节数和 SHA-256 均一致；另有 7 条 `deleted: true` 的删除标记，不应要求其有内容文件。
- SQL 文件版本不是每条内部 SQL 执行的独立日志；命令调用脚本时，不能仅由命令与文件版本保证还原其内部每次改写、查询或数据库瞬态。
- **返回记录：** 832 个请求均有 `cause` 对应的工具返回。其中 **831 个为 run observation**，具有输出字符串与退出码；**1 个为 error observation**，没有命令退出码。命令索引与前述 831 个正常 run observation 的动作 id 完全对应。
- **需要纠正的表述：** HANDOVER 将 832 称作 bash 命令数；更精确的口径是 832 个 bash 动作请求。impl-020 的 event 47 对应 event 48 的 `observation=error`，记录末尾为 `embedded null byte`，且没有进入执行侧录。这里仅记录原始事件类型，不分析其与任务得分或数据错误的关系，也不改写原 HANDOVER。
- **完整性的边界：** 记录包含模型对外输出、命令与返回观察，但不是完整 HTTP 请求/响应抓包、隐藏推理或逐步数据库快照。已核对官方输出截断代码，存在 `Observation truncated due to length` 标记；stdout/stderr 合并，不能声称每条命令的原始输出都无截断。模型尝试、工具请求、实际命令执行与文件数须分开计数。
